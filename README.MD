Paper ARPG is a working title.

Engine: Godot
Reason: Lightweight, Open Source, Moddable with Plugins, Free

A column about AI use
This project will use AI in what I feel is a meaningful way. There will be no AI generated Art as part of the project. There will be no AI generated sound as part of the project.

Code can be generated by an AI, but only as an assistant. The developer of the project is a software developer and must understand and know all shipped code.

AI will not be used for Game Design, World Building, Text Drafting, etc...
In other words, any piece of content the user can see or interact with as part of the experience, may not be AI generated.

This project has 3 distinct goals:

- Create an ARPG that can be enjoyed on the go (iOS, Steam Deck, Nintendo Switch 2)
- Have deep and meaningful progression in builds, gear and content you can pursue
- Be easily extendible both vertically (harder bosses, higher level-cap) and horizontally (new classes, new weapons, new builds)

The prototype of this game should be a vertical slice of the early game content of the game.
It should prove the following concepts:

- Can the UI be tailor made to Controller and/or Touch controls as the main driver?
- Can the game be enjoyed in bite-size sessions, with each session offering some sort of possibility to progress in the game.
- Does the game feel snappy and well-made

In terms of art style, I think we should keep it as simple as possible for now. We'd use Kenney Assets in either 2D or 3D.
Potential art styles to explore would be

- Paper Standees
- 3D as 2D (Diablo 1-2 uses this technique, Halls of Torment, ...)

In terms of prototype development, I think we should develop the game step-by-step

1. Movement
   - Movement Abilities
     - Basic Movement
     - Blink/Teleport Abilities
     - Leap Abilities
   - Movement Animations and feedback
2. Spawning Basic Enemies
   - Enemies have an aggro radius
   - Once in aggro, they will pathfind to the player
   - They will pathfind around obstacles, through corridors and might even have movement abilities of their own
3. Basic Combat
   - What will our combat system be?
   - Will we use telegraphed abilities (ie. Wild Star, League of Legends, ...)
   - How will it fit in the control scheme
   - A Fireball skill that can be aimed
   - A curse skill that must be targeted

At the end of these 3 steps we do a first playtest. The game will be very basic, but the controls should be validated. Only if they feel good, will we continue.
